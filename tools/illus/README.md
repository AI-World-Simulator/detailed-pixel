# Анимация иллюстрированного (не пиксельного) жителя: эксперимент

Один житель, три подхода, всё локально на M3 Max 64 ГБ через общий ComfyUI (`--cache-none`: каждая задача заново грузит модель).
Демо: [`demo.html`](demo.html) (открыть из файла; ассеты в `assets/`), снимок — [`demo.png`](demo.png).

## Итог

- **A — покадровые правки Qwen-Image 2.1** дают самую живую анимацию: у каждого кадра своя мимика, волосы, поворот головы.
  Цена — ~100 с GPU на кадр и разброс, который чинится автоматически (рост фигуры, линия земли, тон).
  Слабое место — ходьба: вторую опорную фазу шага промптом получить не удалось (4 из 4 попыток — та же нога впереди).
- **B — кукла из одного рисунка**: самая дешёвая в рантайме (34 КБ на все детали против 273 КБ кадров A), пропорции стабильны
  по построению, тайминги любые. Но голова — одна картинка: нет поворотов, волосы не живут; ходьбы без разбиения ног нет.
- **C — image-to-video, Wan 2.2 TI2V-5B**: локально на этом Mac **непригоден — известный баг MPS** (ComfyUI #15793, #16644):
  кадры после первого тихо портятся (выгорание, пятна, красное месиво), в fp16, bf16 и fp32 одинаково. Чистым выходит только
  почти неподвижный покой ≤ 17 кадров; взмах ломается уже на 9 кадрах. Подробности — раздел C.
- **C2 — image-to-video, LTX-2.5 (22B distilled, GGUF Q8)**: **работает локально** (18.10.2026). Взмах и покой по 49 кадров
  512×672 без брака: цвета держатся (насыщенность 24,6–25,4 во всех кадрах), рука поднимается, машет и опускается, ноги на
  месте, лицо узнаваемо. ~4–4,5 мин на клип вместе с загрузкой 47 ГБ весов. Раздел C2, `ltx.py`.
- **Qwen-Image-Layered** не запускали: 57 ГБ bf16-весов, fp8 на MPS не работает (проверено), GGUF требует кастомный узел и перезапуск общего сервера.
- **Правило «голова из базы» для иллюстраций отменено** (решение пользователя после облачных анимаций). Вклейка головы базы
  (вариант A′ в демо) делает лицо идентичным, но анимацию мёртвой. Ограничение теперь другое: без бессмысленных скачков пропорций
  и формы (голова вдруг меньше/больше, «плывущие» черты, прыгающий объём) и без скольжения/парения ног. Метрики ниже — об этом.
  Инвариант «Лицо» в `docs/character-animation.md` §2 написан для пиксельного лоадера; для иллюстраций его стоит переформулировать
  (документ в этом эксперименте не менялся).

**Рекомендация**
- (a) **Маленькие жители на карте** — A: кадры Qwen с автоматической нормализацией (рост, земля, тон) и наложенными морганиями.
  На ~75 px лицо почти не читается, важны силуэт и ходьба. Позы покоя, разговора, взмаха Qwen делает с первой попытки;
  цикл ходьбы с правильным чередованием ног — добирать облачным генератором циклов (Ludo/SpriteCook, проверить на одном жителе)
  или видео-моделью. Дыхание/покачивание можно добавить CSS-трансформом поверх кадров (как у B), это бесплатно.
- (b) **Говорящий портрет в карточке** — B (кукла): наклоны, дыхание, моргания и рот в реальном времени, 45 КБ, без генераций на реплику,
  любые тайминги под текст. Если не хватит жизни — 2–3 доп. патча бровей/рта из тех же правок; следующий шаг — Live2D
  (повороты головы, физика волос) или LivePortrait/Hedra для заранее записанных клипов.
- (c) **Крупные катсцены** — видео-модель. Облачные Kling/Veo/Runway (первый+последний кадр — петли, альфу снимаем
  BiRefNet, как в C); для реплик — Runway Act-Two. Локально — **LTX-2.5** (раздел C2: 5–10 с при 512×672 за 4–9 мин,
  апскейл ×2 по желанию); Wan 2.2 на MPS не годится (раздел C);
  для мелких жителей видео избыточно: 0,5 МБ на 2 с одного действия против 34 КБ на всю куклу.

## Запуск

```bash
PY=~/ComfyUI/.venv/bin/python
cd tools/illus
python3 gen.py jobs/z_base.json raw/z --batch        # база: Z-Image-Turbo, 3 сида; выбран s11 -> cp raw/z/z_base_s11.png raw/base.png
python3 gen.py jobs/m_base.json raw/m                # BiRefNet-маска базы
python3 gen.py jobs/q_edits.json raw/q --batch       # Qwen-Image 2.1 edit: blink, talk, wave×2, walkA×2, walkB×2, noarm×2
python3 gen.py jobs/q_edits2.json raw/q --batch      # walkB ещё ×2, «проход» со словом walking ×2 (не вышло)
python3 gen.py jobs/q_edits3.json raw/q --batch      # «проход» без слова walking ×2 (вышло)
python3 gen.py jobs/q_edits4.json raw/q --batch      # «проход» на другой ноге ×2
for j in m_edits m_edits2 m_edits3 m_edits4; do python3 gen.py jobs/$j.json raw/m --batch; done
$PY frames.py                                        # A: raw/a/*.png + metrics_a.json (выбранные сиды — PICK в frames.py)
$PY puppet.py                                        # B: raw/b/*.png + raw/b/parts.json
python3 gen.py jobs/wan_idle_bf16.json raw/c         # C: Wan 2.2 TI2V-5B (bf16) + BiRefNet на каждый кадр в одной задаче
$PY video.py v_idle_bf16 idle --full                 # C: альфа, метрики -> raw/c/video_meta.json (--full: весь клип, без петли)
                                                     # jobs/wan_idle.json — прогон fp16 (33 кадра), jobs/wan_wave.json — не запускали
$PY build_assets.py                                  # WebP-ленты и детали -> assets/, manifest.js
$PY sheet.py out.png raw/a/base.png raw/a/wave.png   # контактный лист с линией земли (посмотреть глазами)
```

- `gen.py` — обёртка над `tools/ai/cgen.py`: выход в `ComfyUI/output/illus/`, входы `illus_*`, плюс граф Wan (тайловый VAE + BiRefNet в той же задаче).
- `dl_models.sh` — загрузка весов Wan (aria2 ×12, sha256 с Hugging Face, отметки в `~/ComfyUI/user/downloads/verified`).
- `common.py` — общие помощники (альфа, снятие фона с краёв, поиск головы, линия земли); `raw/` в `.gitignore`, всё в нём пересобирается.
- Демо: `assets/manifest.js` (геометрия, размеры, метрики — пишет `build_assets.py`), `assets/notes.js` (подписи, руками).

## База

Z-Image-Turbo, 768×1024, 8 шагов: «2D illustrated game character, full body, 3/4 front view, … soft cel shading, plain flat
very light grey background, no shadow». 3 сида по ~48 с. s13 нарисовал тень на земле (мешает маске), s11 выбран за зазор между
руками и телом (проще вырезать руку). Стиль вышел плоским «векторным», без тёмного контура — для BiRefNet это хорошо, края чистые.

## A. Покадровые правки (Qwen-Image 2.1 edit + обработка)

**Шаги** (`frames.py`):
1. маска BiRefNet → снятие фона с полупрозрачных краёв (цвет края без серого ореола);
2. поиск головы базы в кадре (корреляция градиентов, масштаб 0,84–1,10; если модель перерисовала голову — по шее силуэта);
3. **нормализация роста**: если голова на ≥ 2 % меньше/больше, кадр масштабируется от стоп так, чтобы шея была на высоте базы
   (если голова в порядке, а тело ниже — это поза, не трогаем);
4. **линия земли** по нижнему ряду обуви; по горизонтали: стоячие кадры — по стопам (не скользят), шаги — по шее;
5. перенос тона к базе (среднее/разброс по каналам): Qwen смещает тон на 1–3,6 уровня за правку, без этого кадры мерцают;
6. **моргания для поз**: закрытые глаза из правки «blink» поверх собственных глаз кадра — только если голова кадра — та же голова базы со сдвигом.

Своя голова каждого кадра сохраняется (мимика, пряди, поворот). Вариант A′ — прежнее правило с вклейкой головы базы — оставлен для сравнения.

**Время:** правка 768×1024 — 93–112 с (включая перезагрузку 20B-модели, сервер в `--cache-none`); BiRefNet 9 с; обработка 6 с на все кадры.
Для A сгенерировано 16 правок, в дело пошли 8 (blink, talk, wave, wave2, walkA, walkB, pass, pass2) → 15 кадров с близнецами-морганиями.
Одна правка простояла 18 мин в очереди за задачами другой сессии — в общем сервере это нормально.

**Размер (WebP):** 15 кадров — 273 КБ в карточке (300×564), 73 КБ на карте (85×160); портрет 3 кадра 482×520 — 63 КБ.

**Замеры пропорций и формы** (`metrics_a.json`; голова/рост/площадь — доля от базы; земля и скольжение — px на холсте 768×1024;
тон — разница средних по каналам, 0–255; «сырой → итог»):

| Кадр | Голова, масштаб | Рост фигуры | Площадь силуэта | Земля сырая | Ноги скользят (стоя) | Дрейф тона |
|---|---|---|---|---|---|---|
| blink | 1,00 | 1,000 | 1,000 | 0 | 0,4 | 1,9 → 0,05 |
| talk | 1,00 | 1,001 | 1,001 | 0 | 0,7 | 1,5 → 0,05 |
| wave | 1,00 | 1,000 | 1,013 | 1 | 0,5 | 2,9 → 0,08 |
| wave2 | 1,00 | 1,000 | 1,021 | 1 | 0,7 → 1,2 | 2,2 → 0,07 |
| walkA | 1,00 | 0,999 | 0,963 | 1 | — | 2,0 → 0,10 |
| walkB | **0,96** → 1,00 | **0,974** → 0,999 | 0,912 → 0,959 | **20** | — | 3,6 → 0,10 |
| pass | 1,00 | 0,991 | 0,987 | 8 | — | 1,6 → 0,09 |
| pass2 | **0,98** → 1,00 | 0,984 → 1,000 | 0,968 → 1,000 | **21** | — | 1,1 → 0,09 |

- Кадры лица (blink, talk) и взмаха Qwen держит отлично: голова 1,00, рост и земля на месте, ноги сдвигаются ≤ 1,2 px.
  В talk модель сама подняла брови и шире открыла глаза — естественная мимика, её и оставляем.
- В позах шага модель дважды нарисовала фигуру на 2–4 % меньше и на 20 px выше: без нормализации голова «проваливалась» бы на каждом шаге.
- **Ходьба:** Qwen не различает «ближнюю/дальнюю ногу». 4 попытки второй опорной фазы (walkB) дали ту же ногу впереди;
  2 попытки «прохода» со словом *walking* дали снова опорную фазу. «Проход» (одна нога стоит, другая поднята) вышел, только когда в промпте
  нет слова walking (2 из 2), но на другой ноге — едва заметно (1 из 2). Итоговая петля «опора → проход → опора → проход» читается как шаг,
  но обе опорные фазы на одной ноге. В 6 из 12 шаговых правок модель повернула голову по ходу движения — естественно, но для петли
  нужны кадры с одинаковым поворотом. Правильный цикл — ControlNet по позе, видео-модель или облачный генератор циклов.
- **A′ (вклейка головы базы)**: лицо идентично, но голова «приклеена»: нет поворота при шаге, волосы неподвижны,
  на шее и по краю причёски были швы (спрятаны под воротник, голова под телом). Отклонено.

## B. Кукла из одного рисунка (cut-out)

**Детали** (`puppet.py`, всё автоматически, без рисования):

| Деталь | Откуда |
|---|---|
| рука (висит) | пиксели базы, которых нет (или они другого цвета) в правке Qwen «без руки» |
| тело за рукой | из той же правки «без руки» (модель дорисовала бок свитера и брюк) |
| голова | геометрия: всё выше воротника (самая узкая строка шеи + шея до воротника) |
| шея | полоска шеи, продлённая на 40 px вверх, под подбородок |
| поднятая рука + предплечье | из кадра взмаха A: всё вне силуэта тела; предплечье — компонента цвета кожи над манжетой |
| закрытые глаза, открытый рот | патчи из правок blink/talk (только изменившаяся область, растушёвка 2 px) |

**Шарниры** найдены по маскам: шея (386, 299), плечо (473, 364), локоть поднятой руки (548, 332).
**Порядок слоёв:** шея → голова (+ глаза, рот) → тело от воротника вниз → рука. Воротник перекрывает низ шеи головы, поэтому наклон головы не даёт щели.

**Анимация (CSS, только transform/opacity, неровные тайминги):** дыхание — `scale(1.004, 1.009)` от стоп (макушка поднимается на ~8 px холста),
вдох 1,5–2,1 с, выдох 1,9–2,7 с; голова — случайные наклоны ±2,2° и кивки до 1,2 px (1,3–2,6 с, ease-in-out); моргания раз в 2–6 с
(15 % двойных); рот 110–190 мс с паузами-словами 250–400 мс; взмах — смена детали (висящая рука отлетает на 28° и прячется,
появляется поднятая), предплечье качается вокруг локтя ±10° по 300–400 мс.

**Что пришлось чинить:**
- Светлый шов на плече поднятой руки: край тела сглажен (полупрозрачный), в щель виден фон. Решение — рука заходит на тело на 5 px.
- Голова с растушёвкой по шее давала полупрозрачные кончики волос — голову режем по воротнику, без растушёвки.
- Поворот висящей руки от плеча на 130–150° (ряд «рука целиком» в демо) не работает: рукав тянется трубой, ладонь не той стороной.
  Нужна смена детали (поднятая рука) — как attachments в Spine — и сустав локтя.
- Бок свитера за рукой — из правки «без руки»: модель дорисовала лишнюю складку, но на месте руки её не видно.
- Сборка куклы в покое совпадает с базой: средняя ошибка 0,15 уровня, 41 px силуэта (0,03 %).

**Время:** +1 правка «без руки» (~100 с; правки blink/talk/wave — общие с A), сборка 1,6 с.
**Размер:** все детали 34 КБ (карточка), 10 КБ (карта), 45 КБ (портрет).

## C. Image-to-video (Wan 2.2 TI2V-5B)

**Веса:** `wan2.2_ti2v_5B_fp16` 10 ГБ + `umt5_xxl_fp16` 11,4 ГБ + `wan2.2_vae` 1,4 ГБ = 22,8 ГБ
(fp8-энкодер из шаблона на MPS не работает). Загрузка ~2 ч: 1–5 МБ/с, параллельно шла загрузка LTX-2.5 другой сессией.

**Граф** (`gen.py`, kind `wan`): `Wan22ImageToVideoLatent` (первый кадр = база) → KSampler uni_pc/simple, 20 шагов, CFG 5,
shift 8 (как в шаблоне ComfyUI) → `VAEDecodeTiled` (512 px, 16 кадров) → BiRefNet на каждый кадр в той же задаче → `video.py`
(альфа, метрики, поиск точки петли).

| Прогон | Сэмплинг | Вся задача | Брак |
|---|---|---|---|
| 576×768, 33 кадра, fp16 (по умолчанию для fp16-весов) | 11,5 с/шаг, 3 мин 50 с | 9 мин 14 с | с кадра 5 (0,21 с) краски выгорают: свитер неоново-жёлтый, руки красные, лицо белое; фон в пятнах; разница с кадром 0 до 67 уровней |
| 576×768, 49 кадров, bf16 (`ModelComputeDtype`) | 14,4 с/шаг, 4 мин 47 с | 12 мин 43 с | позже, с кадра 9 (0,38 с), но так же; к концу светящееся пятно на груди; до 70 уровней |

- **Форма и земля** стабильны: голова 1,00 во всех кадрах, рост ≤ +0,6 %, площадь ≤ +3,3 %, земля 0 px, стопы ≤ 1,3 px.
  Само движение спокойное (дыхание, лёгкие движения головы) — то, что нужно для покоя. Ломается именно цвет и фактура.
- **Причина — баг MPS, не наш граф** (проверено 17.10, сид 31, 576×768, 20 шагов, CFG 5):

  | Прогон | Итог |
  |---|---|
  | VAE туда-обратно, 33 одинаковых кадра | чисто: 47–48 дБ, насыщенность не плывёт (на стыках временных тайлов 12/24 — до 24,6 дБ; лечится большим `temporal_size`) |
  | 33 кадра, bf16 + внимание в fp32 (`COMFY_UPCAST_BF16=1`) | тот же брак, что fp16 |
  | 33 кадра, **fp32** (23 мин) | тот же брак — точность ни при чём |
  | покой, 9 кадров | **чисто**, есть живое движение (наклон головы, улыбка) |
  | покой, 17 кадров | почти чисто (насыщенность 24 → 27, скачок фона на стыке тайлов) |
  | взмах, 9 кадров | **месиво с первого кадра** (красно-чёрный силуэт) |

  Это открытый баг Wan 2.1/2.2 на Apple Silicon: [ComfyUI #15793](https://github.com/Comfy-Org/ComfyUI/issues/15793)
  (не зависит от точности, способа внимания и версии torch; зависит от длины клипа и чипа),
  [#16644](https://github.com/comfy-org/ComfyUI/issues/16644). Обхода нет; выживает только почти неподвижный кадр.
- **Петля:** у TI2V-5B нет условия на последний кадр; `video.py` ищет кадр, похожий на первый, но после «выгорания» такого нет —
  в демо показан весь клип (25 кадров, 12 к/с).
- **Размер:** 537 КБ в карточке, 129 КБ на карте — в 2 раза больше всех 15 кадров A и в 16 раз больше куклы.
- Взмах (9 кадров, `jobs/wan_len.json`) развалился сразу — см. таблицу выше.

## C2. Image-to-video (LTX-2.5) — работает

**Веса** (MPS-совместимые вместо int8 из шаблона): `ltx-2.5-22b-distilled-Q8_0.gguf` (ComfyUI-GGUF), Gemma 4 12B bf16,
видео-VAE bf16; ~47 ГБ в памяти за задачу. **Сервер** — с `COMFY_UPCAST_BF16=1` (внимание bf16 → fp32), иначе на MPS
чёрное видео (ComfyUI #15804).

**Граф** (`ltx.py`): одна ступень официального шаблона `video_ltx2_5_i2v` в базовом разрешении — без латентного апскейла и
без улучшателя промпта; латент только видео (без звука); `LTXVImgToVideoInplace` (первый кадр = база), distilled-сигмы в 8 шагов,
`euler_ancestral`, CFG 1, тайловый декод с `temporal_size` 64.

| Прогон | Время (с загрузкой моделей) | Итог |
|---|---|---|
| смоук, 9 кадров 256×352 | 3 мин 46 с | чисто, плавно моргает и улыбается |
| **взмах, 49 кадров 512×672** | 4 мин 10 с | **чисто**: рука поднимается, машет, опускается; насыщенность 24,6–25,4 |
| покой, 49 кадров 512×672 | 4 мин 35 с | чисто: моргание, наклон головы, улыбка |
| цепочка действий, **121 кадр (5 с)** 512×672 | 4 мин 20 с (сэмплинг 2:41, 20 с/шаг) | чисто: машет → руки в боки → смеётся; насыщенность 24,8–26,4 |
| цепочка действий, **241 кадр (10 с)** 512×672 | 8 мин 46 с (сэмплинг 6:52, 52 с/шаг) | чисто: вся цепочка, включая возврат в покой; насыщенность 24,7–27,0; своп +1,2 ГБ |

| **апскейл ×2** того же 121-кадрового черновика → 1024×1344 (`ltx.py --upscale`) | 11 мин 34 с (3 шага доводки по ~175 с) | движение, позы и тайминг кадр в кадр как в черновике; контуры и глаза чёткие вместо размытых; мимика местами чуть другая |

Порядок работы: черновик 512×672 (~5 мин на 5 с) → посмотреть → апскейл только удачного (~11–12 мин). Черновик
сохраняет латент (`SaveLatent`), апскейл — вторая ступень шаблона: латентный апсемплер ×2 + 3 шага (сигмы 0,85 → 0)
с тем же промптом и первым кадром = база в полном размере.

Длина: кадров 8n+1; ×2 кадров → ×2,6 времени сэмплинга (внимание квадратичное). 10 с при 512×672 — проверено, больше
не пробовали (20 с ≈ 20 мин сэмплинга по оценке, риск ошибки MPS «tensor dims larger than INT_MAX»). Длинное видео
выгоднее собирать сегментами в одной задаче: ключевые кадры (Qwen) + сегменты с первым/последним кадром (`LTXVAddGuide`),
стыки — перекрытием латентов (`LTXVAddLatentGuide`), а не одним последним кадром (рывок на стыке и накопление дрейфа).

То же самое у Wan: взмах на 9 кадрах — месиво (раздел C). Мелочи: машет левой рукой вместо правой; не проверены длинные
клипы (97+ кадров), вторая ступень (апскейл ×2), петля через первый = последний кадр (`video_ltx2_5_flf2v`).

## Qwen-Image-Layered — пропущен

ComfyUI 0.41.2 его умеет (`EmptyQwenImageLayeredLatentImage`, шаблон `image_qwen_image_layered.json`), но:
- веса: `qwen_image_layered_bf16` 40,9 ГБ + текстовый энкодер `qwen_2.5_vl_7b` bf16 16,6 ГБ = 57 ГБ (лимит эксперимента ~40 ГБ; при 1–5 МБ/с это 3–15 ч);
- fp8-варианты (≈20 + 8,7 ГБ) на MPS не работают: `float8_e4m3fn` переносится на MPS, но приведение к bf16 падает (`Undefined type Float8_e4m3fn`, проверено);
- GGUF требует узел ComfyUI-GGUF и перезапуск общего сервера — нельзя;
- по описанию модель делит картинку на семантические слои (фон/фигура/текст), а не на конечности, и медленная (в шаблоне 50 шагов, CFG 4).
Детали для B получены правками Qwen 2.1 + BiRefNet + геометрией.
