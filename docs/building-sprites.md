# Спрайты зданий из ИИ: как делать сразу хорошо

Документ собирает итоги экспериментов 16–17.10.2026, чтобы в следующей сессии их не повторять. Подробные отчёты с картинками и цифрами:
- [reports/Спрайты зданий из ИИ.md](../reports/Спрайты%20зданий%20из%20ИИ.md): болванки, рецепты Z-Image и Qwen, фото, камера;
- [reports/Codex для арта игры.md](../reports/Codex%20для%20арта%20игры.md): что умеет Codex (GPT Image) и что ему отдавать.

Скрипты лежат в [tools/ai/lab/](../tools/ai/lab/), их назначение описано в README там же.

## Главное за 30 секунд

- **Модель рисует, генератор задаёт форму.** Каждое здание начинается с **болванки**: простой 3D-коробки, отрендеренной в нашей камере. Генератор знает участок, угол, этажность и тип крыши. Модель превращает болванку в красивый дом и попадает в угол и силуэт с IoU 0.92–0.99. Без болванки модель рисует ракурс и пропорции на свой вкус.
- **Стиль выбран: «пластилин»** (эталон [docs/art-style-clay.webp](art-style-clay.webp), нарисован Codex). Арт делает ИИ, вручную не рисуем, 3D-моделей нет.
- **Камера: ортографическая, наклон 55°.** Рецепт листа R1 при 55° проверен (IoU 0.99). При 30° здания закрывают людей на улицах, см. раздел «Камера».
- **Массовая застройка — спрайты по типам.** Тип = лист из 8 ракурсов; дом нужной длины собирается из повторяемых пролётов, цвета перекрашиваются кодом. Рисовать район целиком одной картинкой пользователь отверг: такую картинку невозможно обновлять по одному дому.
- **Два генератора:**
  - **Codex** (GPT Image через ChatGPT) лучше всех держит выбранный стиль и рисует листы типов по болванке с IoU 0.92–0.97. Но лимит подписки кончается примерно на 90 картинок за окно в 5 часов, а этажей он рисует на один меньше.
  - **Локальный ComfyUI** (Z-Image, Qwen) детерминирован и без лимитов, но пластилин у него выходит проще и игрушечнее.
- **Рабочий пример:** [experiments/moscow-block/index.html](../experiments/moscow-block/index.html) — квартал центра Москвы из генератора (146 домов), собранный из спрайтов, с людьми.

## Окружение

- **Где лежит:** ComfyUI в `~/ComfyUI` (v0.41.2, Python 3.12 venv, PyTorch на Metal), описание в `~/ComfyUI/LOCAL_SETUP.md`.
- **Запуск и остановка:** `~/ComfyUI/start.sh` и `~/ComfyUI/stop.sh`, сервер http://127.0.0.1:8188. Работа идёт через HTTP API: `POST /prompt` с workflow в API-формате, затем опрос `GET /history/<id>`.
- **Модели** (bf16, все проверены по sha256):

  | Модель | Файлы |
  |---|---|
  | Z-Image-Turbo | `z_image_turbo_bf16`, энкодер `qwen_3_4b` (CLIPLoader type `lumina2`), `ae` |
  | ControlNet для Z-Image | `Z-Image-Turbo-Fun-Controlnet-Union-2.1-2602-8steps` (ModelPatchLoader → ZImageFunControlnet) |
  | Qwen-Image-2.1 | `qwen_image_2.1_bf16` + LoRA `qwen_image_2.1_turbo_lora_avg_rank_178_bf16`, энкодер `qwen3vl_8b_bf16` (type `qwen_image`), `qwen_image_2.1_vae_bf16` |
  | ControlNet для Qwen | `qwen_image_2.1_fun_controlnet_union_bf16` |

  Догрузить или проверить модели: `~/ComfyUI/user/downloads/dl_all.sh`.
- **Грабли окружения, уже исправленные в `start.sh`:**
  - **Сон Mac.** Он засыпает через 1 минуту простоя, и генерация замирает посреди шага. `start.sh` держит Mac бодрствующим через `caffeinate -w <pid сервера>`, пока работает сервер.
  - **Память.** На 64 ГБ Qwen (~32 ГБ) и Z-Image (~20 ГБ) вместе в кэше дают своп 28 ГБ, и задача идёт 20–50 минут вместо 2. Поэтому сервер работает с `--cache-none`: модели выгружаются после каждой задачи, перезагрузка с SSD занимает секунды.
  - **Предел размера на Metal.** Холст больше ~2 Мп падает в VAE с ошибкой «MPSGraph does not support tensor dims larger than INT_MAX». 2048×1024 работает, 2560×1536 нет.
- **Сервер общий** с другими сессиями: задачи стоят в одной очереди. `"front": true` в теле `/prompt` ставит задачу в начало очереди, пользуйтесь этим только для коротких срочных задач и договаривайтесь с соседями. Не перезапускайте сервер, пока у кого-то идут задачи.
- **Codex:** скилл `codex` (обёртка `~/.claude/skills/codex/scripts/codex_run.py`), картинки собираются в `<run dir>/images/`.
  - **Каждому вызову — своя папка `--out`.** Два вызова в одной папке портят друг другу thread id, и картинка теряется.
  - Вызов идёт 1–5 мин, параллельно можно до ~16.
  - Пользователь разрешил тратить без счёта, но **окно подписки кончается примерно за 90 картинок**: «usage limit … try again at HH:MM». Держите локальный запасной путь и сохраняйте результаты.
- **Лицензии.** Qwen-Image-2.1 под исследовательской (некоммерческой) лицензией, Z-Image под Apache-2.0. Проект некоммерческий, поэтому это допустимо. Условия OpenAI запрещают программное извлечение Output и обучение конкурирующих моделей на нём: массовая генерация через подписку и LoRA на картинках Codex — серая зона.

## Болванки и соглашения

Генератор болванки: `tools/ai/lab/proxy2.py OUT ANGLE [hip|gable|flat] iso [tall]`, параметры задаются переменными окружения.

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `PL`, `PD` | ширина фасада со входом и глубина, м. Если задана любая из них, кадр подгоняется под здание | 34, 13 |
| `PFL`, `PFH` | этажи и высота этажа | 5, 3.1 |
| `PRIDGE` | подъём крыши, м | 4 |
| `PAXIS` | `u`: конёк вдоль улицы; `n`: фронтон на улицу | u |
| `PPITCH` | наклон камеры, ° | 30 |
| `PWALL`, `PROOF` | цвет стен и крыши, hex без `#` | кремовый, терракота |
| `PDOOR` | номер пролёта с дверью | средний |
| `PLIGHT` | направление на солнце `x,y,z` | `-0.5,0.4,0.75` |
| `PTAG` | суффикс имени файла | — |

- **Угол:** 0° значит, что фасад с дверью смотрит на зрителя. С ростом угла фасад поворачивается влево: 90° — фасад смотрит влево, 180° — задом к зрителю. Так же считают `tools/ai/angle_sheet.py` и `measure_sheet.py`.
  Внимание: самые ранние прогоны (раунды r1–r5) шли с зеркальной конвенцией.
- **Выходные файлы болванки:**
  - `_colorn`: цветная с шумом, для первого шага img2img и как подсказка для Codex;
  - `_lines`: силуэт и рёбра;
  - `_linesw`: силуэт, рёбра и окна;
  - `_mask`: маска силуэта для проверки и вырезания;
  - `_faces`: какая грань какая (1 — фасад, 2 — торец, 10+ — скаты крыши);
  - `_umap`: координата вдоль фасада для каждого пикселя (16 бит, u = v/100 − 300 м), для нарезки на пролёты;
  - `_meta.json`: проекция (масштаб, центр, наклон);
  - `_depth`, `_gray`: доступны, но не пригодились.
- **`tall`** рисует высокие окна XIX века (1×1.8 м). С ними фасады выходят заметно лучше, чем с квадратными окнами.
- **Лист ракурсов:** `tools/ai/lab/sheet_proxy.py IN NAME COLS CELL ANGLES…` с переменной `PAT`, или `block_types.py` для типов квартала. Масштаб общий для всех ячеек.
- **Свет:** солнце сверху-слева. Модель берёт свет из затенения болванки на первом шаге, отдельно задавать его не нужно.

## Стиль

- **Как выбирали.** Доска из 9 игровых стилей (пиксель-арт, мультяшный с обводкой, ламповый, low-poly, «ясная линия», масло, пластилин, японская анимация, пререндер 90-х). Выводы:
  - **Привязка к болванке гасит стиль** у всех моделей: с цветной болванкой и Codex, и Z-Image рисуют «аккуратный полуреализм».
  - **Codex на одной доске 3×3 доводит стили до крайности, но ломает пропорции** (башня вместо дома 22×13 м). По одной картинке на стиль он держит форму, но смягчает стиль.
  - **Локальный Z-Image без LoRA сильных стилей не делает.** Без цветной основы он теряет дом и рисует «милый 3D-домик» в любом стиле.
- **Пластилин у Codex:** эталон стиля второй картинкой, промпт `tools/ai/lab/codex_prompts/t2_colorn_a.txt` (лист) или `t1_color_c.txt` (один вид). Эталон копирует материал, а не здание, если явно написать «STYLE REFERENCE ONLY, do not copy its building».
- **Пластилин локально (Z-Image):** промпт `CLAY` в `exp.py` (`clay_msk`, `clay_sheet_<тип>`), рецепт R1. Материал узнаваемый, но проще и игрушечнее эталона. Под домом появляется серая подставка, на фоне мягкая тень, её срезает нарезка.
  - Линии окон 0.45 обязательны: при 0.35 модель теряет этажи (2–3 вместо 4) и добавляет мансарды.
  - Без цветной основы (только линии) получается двухэтажный домик, форма потеряна.
- **Ассеты в пластилине** (деревья, кусты, фонарь, скамейка, киоск, клумба) Z-Image рисует отлично: `block_assets.py`. Ракурс у них скорее сбоку, для мелочей это нормально.

## Рецепты: что работает

### R1. Дом по описанию → лист ракурсов (Z-Image-Turbo), основной путь массовой застройки

- **Лист:** 4×2 ячейки по 512 px = 2048×1024.
  - Для повторно используемых типов: ракурсы 0, 15, …, 90°, остальные зеркалом через `cut_sheet.py --mirror`. Зеркало честное, если свет симметричный или здание симметрично спереди-сзади.
  - Для района: ровно те 8 углов, которые встречаются в районе (`block_types.py`), без зеркал и без ошибки угла.
- **Параметры:** img2img от `_colorn`, `denoise 0.85`. ControlNet по **`_linesw`** (с окнами), `end_percent 0.8`, сила **0.45 при наклоне 55°** (IoU 0.99, раунд r11) и 0.35 при 30° (при 30° сила 0.45 давала плоские «панельные» фасады).
- **Промпт:** описание дома + явно «five rows of windows» + «one building shown N times, exactly the same building in every view» + камера. **При 55° уберите «2:1 isometric»** и напишите «orthographic game view from high above, tilted steeply down at about 55 degrees, roofs large and clearly visible» (`p3_sheet5_7_top`).
- **Время:** ~4–5 мин на лист.

Пример вызова из скрипта:

```python
import sys; sys.path.insert(0, "tools/ai/lab"); import exp
cfg = dict(proxy="blk_hip4", init="colorn", d=0.85, ctrl="linesw", s=0.45, e=0.8, prompt="clay_sheet_hip4")
exp.post("/prompt", {"prompt": exp.wf(cfg, seed, "exp/blk_clay_hip4")})
```

### R1c. Лист типа в Codex (по цветной болванке)

- **Картинки:** 1 = `blk_<тип>_colorn.png`, 2 = эталон стиля. Промпт: `codex_prompts/sheet_neutral_<тип>.txt` (нейтральные кремовые стены и серая крыша под перекраску) или `t2_colorn_a.txt`.
- **Результат:** IoU 0.92–0.97 у вальмовых и плоских крыш, 0.86–0.91 у двускатных; 2–3.5 мин, вызовы идут параллельно.
- **Брак:** этажей на один меньше почти всегда; труба привязана к экрану; ячейки сдвинуты на 0–4% и увеличены до 6% (лечит подгонка ячеек в `block_build.py`). У двускатных крыш нужен абзац «STEEP CAMERA» (`t2_gable4_v2.txt`).
- **Правки** (ночь, сезон, перекраска, «переставь двери») сохраняют геометрию: силуэт 0.99–1.00. Прикладывайте картинку как «EDIT TARGET», треды хранить не нужно.

### R1b. То же только на Qwen (красивее Z-Image, медленнее)

- **Один вид:** болванка **первой** картинкой-образцом (`size="ref"`, латент берётся по её размеру), плюс ControlNet по `_lines` с силой 0.7, плюс промпт «Transform image 1: replace the block with …, keep exact shape…, add rich detail…».
- **Результат:** форма 0.95–0.98, правильная этажность, ~290 с на вид.
- **Лист:** болванка-лист первой, ~5.5 мин. Красивее Z-Image, но масштаб плывёт (0.81) и встречаются ошибки, например дверь не на той стене.

### R2. Реальное здание по фото → спрайт под нужным углом

- **Codex:** болванка + фото + эталон стиля (`codex_prompts/t3_izba.txt`), IoU 0.96, ~2.5 мин. Иногда дом увеличен в ~1.2 раза: совмещать масштаб по маске.
- **Локально (Qwen → Z-Image):**
  1. **Qwen:** **болванка первой** картинкой (`_colorn`), **фото второй**, `size="ref"`, промпт `transform_prompt` из `qrounds.py`. Форма точная, внешность с фото, но картинка плоская.
  2. **Z-Image:** img2img от результата шага 1, `denoise 0.75`, ControlNet по `_linesw` 0.4, промпт с **текстовым описанием дома** (`zbeauty.py`). ~3 + ~1.5 мин.

### R3. Лист ракурсов по фото

Как R2 локально, только первой картинкой идёт лист из 13 болванок (0–180°, 1920×1152, `res=1504`), второй — фото. Второй проход по всему листу делает `zbeauty_sheet.py`. Время ~8 + ~8 мин. Покраска стен между ракурсами может плыть, поэтому её лучше назвать в промпте явно.

### R4. Знаковые здания (Кремль, собор, статуя)

- **Codex** по одному фото без болванки рисует крутой вид сверху (55°) очень детально, ~2.5 мин. Лучший вариант.
- **Qwen**, одно фото, режим RGBA: ~2 мин, прозрачный фон сразу, но ракурс модель выбирает сама и 55° словами не держит.
- Такое здание в мире одно, поэтому генератор разворачивает под нарисованный ракурс участок.

### R5. Новый тип дома по описанию → канонический вид

Qwen по тексту, RGBA, ~75–90 с. Стиль держится ровно между странами (машия, шале, риад, купеческий дом, изба). Ракурс модель выбирает сама. Получившийся вид дальше становится референсом для R2 или R3.

### Брак, нарезка, контроль

- **Починка ячеек** (`fix_cells.py`): в сломанную ячейку подставляется её болванка, и ячейка перерисовывается по маске с силой 0.6. Остальной лист служит контекстом и остаётся пиксель в пиксель. Смысловые правки (двери, детали) — правкой Codex.
- **Нарезка** (`tools/ai/cut_sheet.py`): лист превращается в RGBA-спрайты с общим масштабом и точкой привязки, плюс зеркальные ракурсы и `sprites.json`. Для района — `block_build.py` (ниже).
- **Автопроверка** (`qscore.py`): IoU силуэта против `_mask`. Порог фона 24 (было 40: бледные стены и серые плоские крыши терялись). Порог 0.95 для одного вида, 0.93 для ячейки листа; ниже — перегенерировать. Для листа передавайте `single=False`. **Мягкая тень на фоне занижает IoU** (пластилин: 0.68 при верной форме), честнее считать по маске без теней, как в подгонке ячеек `block_build.py`.
- **IoU не видит пропавший этаж:** этажи и двери проверять отдельно (скрипты в отчёте про Codex).
- **Сколько брака:** ~1 из 4–8 сидов уходит мимо, особенно анфас (0°).

## Квартал: от генератора до карты

Рабочий пример: [experiments/moscow-block/](../experiments/moscow-block/), наборы `ai/` (локальный Z-Image), `codex/` (листы Codex), `proxy/` (болванки). Открыть `index.html` двойным кликом; параметры `?set=ai|codex|proxy&z=2&x=0.5&y=0.5`.

- **Что даёт генератор** (Москва, Париж, Нью-Йорк, Стамбул):
  - 97–100% зданий — прямоугольники 12–55 × 9–18 м, высота 7–29 м;
  - крыши: 0 плоская, 1 вальмовая, 3 двускатная, 5 мансарда, 6 шатровая;
  - типов без учёта цвета и длины (стиль, крыша, этажи, глубина) 123 на Москву, 80% зданий покрывают 29;
  - повороты: в районе 4 направления улиц, но в Париже медиана отклонения от сетки 15° — 5°, поэтому углы берём точные по району.
- **Шаги:**
  1. `node tools/ai/lab/block_dump.js moscow -107 -131 130 block_raw.json` — здания, улицы, кварталы, деревья, мелочи из окна города.
  2. `python block_types.py` — 6 типов (`hip|gable|flat` × 4|6 этажей), длина 5 пролётов по 3.25 м, глубина 12.5 м, дверь в пролёте 1, 8 углов района → `blk_<тип>_{colorn,linesw,mask,faces,umap,meta}`.
  3. Листы: локально `python exp.py blk_clay 1,2` (~5 мин на лист) или Codex с `codex_prompts/sheet_neutral_<тип>.txt` (~3 мин, параллельно).
  4. `python block_assets.py gen OUT` — деревья, мелочи и бесшовные текстуры земли в стиле (~20 мин).
  5. `python block_build.py block_raw.json OUT_SET assets=OUT hip4=a.png,b.png hip6=… [alias=flat6:flat4]` — сборка (~40 с).
  6. `python block_pack.py OUT_SET 60` — спрайты и земля в WebP, координаты округлены: ~30 МБ PNG → ~3 МБ на набор (так наборы и лежат в репозитории; PNG в git игнорируются).
- **Как собирается дом** (`block_build.py`):
  - **угол** — ближайший из 8 нарисованных (ошибка в квартале в среднем 2.1°, максимум 4.3°);
  - **подгонка ячейки**: масштаб ±8% и сдвиг до ±32 px по максимуму IoU с маской болванки (Codex рисует ячейки чуть крупнее и со сдвигом);
  - **длина** — пролёты 0, 1 | 2 × k | 3, 4 по карте `_umap`. При неподвижной ортографической камере сдвиг вдоль фасада — постоянный сдвиг на экране, поэтому сборка точная. Ошибка длины в среднем 0.9 м; вальмовой крыше нужно минимум 4 пролёта (13 м);
  - **цвет** — перенос цвета генератора с сохранением яркости, отдельно для каждой грани (фасад, торец, каждый скат), окна и белый декор не трогаются;
  - **вырезание** — маска болванки плюс то, что нарисовано рядом и над крышей (трубы); серые мягкие тени на фоне отбрасываются;
  - **порядок отрисовки** — по столбцам экрана: дом A рисуется после B, если на общем столбце его пятно ближе к камере;
  - **земля** — текстуры асфальта, плитки, травы с пятнами гравия, бордюры, тени домов и деревьев.
- **Результат 17.10** (квартал 240×240 м, 146 домов, 6 типов, 60 fps; сравнение трёх наборов: [experiments/moscow-block/compare.webp](../experiments/moscow-block/compare.webp)):

  | Набор | Листы | Качество ячеек | Вид |
  |---|---|---|---|
  | `ai` (Z-Image) | 12 листов (6 типов × 2 сида), ~5 мин на лист, ~1 ч на общей видеокарте | IoU после подгонки 0.86–0.92 (занижен подставкой и тенью), у 4 типов годятся оба сида | пластилин крупный и игрушечный; на плоских крышах иногда странные «трубы»; торцы вальмы иногда рисует фронтоном |
  | `codex` | 5 листов из исследования (flat6 не успели до лимита, подставлен flat4), ~3 мин на лист | IoU после подгонки 0.955–0.996, сдвиги ≤4 px | ближе всего к эталону: аккуратные окна, чистые плоские крыши; этажей на один меньше |

  Выбор сидов: `python block_pick.py ~/ComfyUI/output/exp/blk_clay 0.88` печатает аргументы для `block_build.py`. Для локальных листов передавайте `align=0`: img2img и так стоит на болванке, а подгонку сбивают подставка и тень.
- **Люди на карте:** ходят по осевым линиям тротуаров. Дом или дерево перед человеком перерисовывается поверх него (клип по рамке человека). Скрытые показываются полупрозрачным силуэтом.
- **Масштаб:** карта 14 px/м (максимальный зум игры ~9 CSS px/м, ~13–18 на ретине). Житель ростом 1.7 м при наклоне 55° — ~14 px, пластилиновой детализации в нём уже не видно: крупные персонажи — отдельный вопрос (портреты, приближение к выбранному жителю).

## Камера и видимость персонажей

- Здание высотой h закрывает за собой полосу улицы длиной **h·ctg(наклона)**.
- Доля улиц, скрытых целиком для человека ростом 1.7 м, по настоящим городам из генератора:

  | Город | 30° | 45° | 55° | 60° | Движок сейчас |
  |---|---|---|---|---|---|
  | Москва | 24% | 16% | 11% | 9% | 10% |
  | Париж | 42% | 32% | 25% | 22% | 22% |
  | Нью-Йорк | 50% | 45% | 39% | 36% | 37% |

  Пересчитать: `node tools/ai/lab/occlusion.js`, `occlusion_streets.py`; картинка с людьми — `occlusion_view.py`.
- **Текущая проекция движка** (земля не сжата, высоты ×0.6) по видимости равна камере с наклоном ~59°, но это не настоящая камера.
- **Модели хорошо рисуют любой наклон 30–60°** (Z-Image, анфас IoU 0.91–0.98), Codex — только по болванке.
- **«Вид 3/4» — это и есть такая камера:** она смотрит на город с юга под наклоном. Наклон рёбер 2:1 бывает только у домов, повёрнутых на 45°.
- **Рекомендация:** наклон ~55°, плюс силуэты людей сквозь здания (сделано в тестовой карте) и полупрозрачность домов вокруг выбранного персонажа.

## ChatGPT / Codex как внешний источник

- ChatGPT рисует ортографическую камеру и держит углы ±4°, если в промпте прямо сказано следить за углами. Без этого 30° и 60° тянутся к 45°. Наклон камеры от листа к листу гуляет: 22–41°.
- **С цветной болванкой первой картинкой** Codex держит и угол, и наклон (53–57°), см. R1c.
- **Каждый лист без болванки замерять:** `tools/ai/measure_sheet.py SHEET OUT [pitch] [angles]`. Допуски: угол ±5°, наклон ±3°. На ячейках с закруглённым цоколем замер наклона врёт (28–43° при IoU 0.98), там проверяйте IoU.
- **Подсказочные листы** с линиями, пятном застройки и болванками: `tools/ai/angle_sheet.py`.
- **Что ещё отдавать Codex** (подробно в отчёте): персонажей (дизайн и повороты, не анимацию), знаковые здания по фото, ночь и сезоны правкой, реквизит по предмету на вызов, текстуры (шов сшивать локально).

## Открытые вопросы и следующие шаги

1. **Выбрать генератор листов для массовой застройки.** Codex точнее по стилю, но лимит подписки (~90 картинок за 5 часов) и условия OpenAI. Локальный Z-Image без лимитов, но пластилин упрощённый. Вариант: LoRA стиля для Z-Image, но учесть пункт ToS о моделях на выходах GPT.
2. **Этажность у Codex** (−1 этаж): проверить локальную доводку — Z-Image img2img от листа Codex с линиями окон, denoise ~0.5.
3. **Задняя сторона и двери.** Сейчас дом с дверью во двор рисуется с дверью на улицу (дверь берётся с уличного фасада); для агентов, входящих в дома, нужен честный двор.
4. **Мансарды и шатровые крыши** (коды 5, 6) пока рисуются вальмовыми; нужны свои типы для Парижа.
5. **Перенести квартал в движок:** спрайты по типам вместо рейкастера улиц, решить камеру 55° окончательно.
6. **Крупные персонажи:** при 14 px/м житель — 14 px; решить, где показывать их крупно.
