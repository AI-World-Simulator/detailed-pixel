# Спрайты зданий из ИИ: как делать сразу хорошо

Документ собирает итоги экспериментов 16–17.10.2026, чтобы в следующей сессии их не повторять. Подробный отчёт с картинками и цифрами: [reports/Спрайты зданий из ИИ.md](../reports/Спрайты%20зданий%20из%20ИИ.md). Скрипты лежат в [tools/ai/lab/](../tools/ai/lab/), их назначение описано в README там же.

## Главное за 30 секунд

- **Модель рисует, генератор задаёт форму.** Каждое здание начинается с **болванки**: простой 3D-коробки, отрендеренной в нашей камере. Генератор знает участок, угол, этажность и тип крыши. Модель превращает болванку в красивый дом и попадает в угол и силуэт с IoU 0.95–0.99. Без болванки модель рисует ракурс и пропорции на свой вкус.
- **Арт делает ИИ, вручную не рисуем, 3D-моделей нет.** Стиль: «уютная» рисованная иллюстрация, вид 3/4, не пиксель-арт, здания под любыми углами.
- **Локальный стек:** ComfyUI плюс две модели. **Z-Image-Turbo** даёт точную форму, быстро. **Qwen-Image-2.1** работает с фото-референсами и сразу выдаёт прозрачный фон.
- **Камера** (решение ещё не принято): рекомендуется настоящая ортографическая камера с наклоном **~55°**. Не 30°, иначе здания закрывают людей на улицах (см. раздел «Камера»).

## Окружение

- **Где лежит:** ComfyUI в `~/ComfyUI` (v0.41.2, Python 3.12 venv, PyTorch на Metal), описание в `~/ComfyUI/LOCAL_SETUP.md`.
- **Запуск и остановка:** `~/ComfyUI/start.sh` и `~/ComfyUI/stop.sh`, сервер http://127.0.0.1:8188. Работа идёт через HTTP API: `POST /prompt` с workflow в API-формате, затем опрос `GET /history/<id>`.
- **Модели** (bf16, все проверены по sha256):

  | Модель | Файлы |
  |---|---|
  | Z-Image-Turbo | `z_image_turbo_bf16`, энкодер `qwen_3_4b` (CLIPLoader type `lumina2`), `ae` |
  | ControlNet для Z-Image | `Z-Image-Turbo-Fun-Controlnet-Union-2.1-2602-8steps` (ModelPatchLoader → ZImageFunControlnet) |
  | Qwen-Image-2.1 | `qwen_image_2.1_bf16` + LoRA `qwen_image_2.1_turbo_lora_avg_rank_178_bf16`, энкодер `qwen3vl_8b_bf16` (type `qwen_image`), `qwen_image_2.1_vae_bf16` |
  | ControlNet для Qwen | `qwen_image_2.1_fun_controlnet_union_bf16` |

  Догрузить или проверить модели: `~/ComfyUI/user/downloads/dl_all.sh`.
- **Грабли окружения, уже исправленные в `start.sh`:**
  - **Сон Mac.** Он засыпает через 1 минуту простоя, и генерация замирает посреди шага. `start.sh` держит Mac бодрствующим через `caffeinate -w <pid сервера>`, пока работает сервер.
  - **Память.** На 64 ГБ Qwen (~32 ГБ) и Z-Image (~20 ГБ) вместе в кэше дают своп 28 ГБ, и задача идёт 20–50 минут вместо 2. Поэтому сервер работает с `--cache-none`: модели выгружаются после каждой задачи, перезагрузка с SSD занимает секунды.
  - **Предел размера на Metal.** Холст больше ~2 Мп падает в VAE с ошибкой «MPSGraph does not support tensor dims larger than INT_MAX». 2048×1024 работает, 2560×1536 нет.
- **Сервер общий** с другими сессиями: задачи стоят в одной очереди. `"front": true` в теле `/prompt` ставит задачу в начало очереди. Не перезапускайте сервер, пока у кого-то идут задачи.
- **Лицензии.** Qwen-Image-2.1 под исследовательской (некоммерческой) лицензией, Z-Image под Apache-2.0. Проект некоммерческий, поэтому это допустимо.

## Болванки и соглашения

Генератор болванки: `tools/ai/lab/proxy2.py OUT ANGLE [hip|gable|flat] iso [tall]`, размеры задаются переменными окружения.

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `PL`, `PD` | ширина фасада со входом и глубина, м. Если задана любая из них, кадр подгоняется под здание | 34, 13 |
| `PFL`, `PFH` | этажи и высота этажа | 5, 3.1 |
| `PRIDGE` | подъём крыши, м | 4 |
| `PAXIS` | `u`: конёк вдоль улицы; `n`: фронтон на улицу | u |
| `PPITCH` | наклон камеры, ° | 30 |
| `PTAG` | суффикс имени файла | — |

- **Угол:** 0° значит, что фасад с дверью смотрит на зрителя. С ростом угла фасад поворачивается влево: 90° — фасад смотрит влево, 180° — задом к зрителю. Так же считают `tools/ai/angle_sheet.py` и `measure_sheet.py`.
  Внимание: самые ранние прогоны (раунды r1–r5) шли с зеркальной конвенцией.
- **Выходные файлы болванки:**
  - `_colorn`: цветная с шумом, для первого шага img2img;
  - `_lines`: силуэт и рёбра;
  - `_linesw`: силуэт, рёбра и окна;
  - `_mask`: маска силуэта для проверки и вырезания;
  - `_faces`: какая стена какая (для метрики света);
  - `_depth`, `_gray`: доступны, но не пригодились.
- **`tall`** рисует высокие окна XIX века (1×1.8 м). С ними фасады выходят заметно лучше, чем с квадратными окнами.
- **Лист ракурсов:** `tools/ai/lab/sheet_proxy.py IN NAME COLS CELL ANGLES…` с переменной `PAT` (шаблон имени, например `p{a}_iso_t_apt`). Масштаб общий для всех ячеек.
- **Свет:** солнце сверху-слева. Модель берёт свет из затенения болванки на первом шаге, отдельно задавать его не нужно.

## Рецепты: что работает

### R1. Дом по описанию → лист ракурсов (Z-Image-Turbo), основной путь массовой застройки

- **Лист:** 4×2 ячейки по 512 px = 2048×1024. Ракурсы 0, 15, …, 90°, остальные получаются зеркалом через `cut_sheet.py --mirror`. Зеркало честное, если свет симметричный или здание симметрично спереди-сзади.
- **Параметры:** img2img от `_colorn`, `denoise 0.85`. ControlNet по **`_linesw`** (с окнами), **сила 0.35**, `end_percent 0.8`. Turbo: 8 шагов, cfg 1, `res_multistep`/`simple`, ModelSamplingAuraFlow shift 3.
- **Промпт:** «уютная рисованная иллюстрация» + описание дома + явно «five rows of windows» + «one building shown N times, exactly the same building in every view».
- **Время:** ~3.5–4 мин на лист.

Пример вызова из скрипта:

```python
import sys; sys.path.insert(0, "tools/ai/lab"); import exp
cfg = dict(proxy="sheet7t", init="colorn", d=0.85, ctrl="linesw", s=0.35, e=0.8, prompt="p3_sheet5_7")
exp.post("/prompt", {"prompt": exp.wf(cfg, seed, "sprites/apt_sheet")})
```

### R1b. То же только на Qwen (красивее, медленнее)

- **Один вид:** болванка **первой** картинкой-образцом (`size="ref"`, латент берётся по её размеру), плюс ControlNet по `_lines` с силой 0.7, плюс промпт «Transform image 1: replace the block with …, keep exact shape…, add rich detail…».
- **Результат:** форма 0.95–0.98, правильная этажность, ~290 с на вид.
- **Лист:** болванка-лист первой, ~5.5 мин. Красивее Z-Image, но масштаб плывёт (0.81) и встречаются ошибки, например дверь не на той стене.

### R2. Реальное здание по фото → спрайт под нужным углом (Qwen → Z-Image)

1. **Qwen:** **болванка первой** картинкой (`_colorn`), **фото второй**, `size="ref"`, промпт `transform_prompt` из `qrounds.py`. Форма получается точной, внешность берётся с фото, но картинка плоская.
2. **Z-Image:** img2img от результата шага 1, `denoise 0.75`, ControlNet по `_linesw` 0.4, «уютный» промпт с **текстовым описанием дома**. Описание нужно составить по фото: вручную или мультимодальной моделью. Результат точный, узнаваемый и красивый. Скрипт: `zbeauty.py`.

Время: ~3 мин + ~1.5 мин.

### R3. Лист ракурсов по фото

Как R2, только первой картинкой идёт лист из 13 болванок (0–180°, 1920×1152, `res=1504`), второй — фото. Второй проход по всему листу делает `zbeauty_sheet.py`. Время ~8 + ~8 мин. Покраска стен между ракурсами может плыть, поэтому её лучше назвать в промпте явно.

### R4. Знаковые здания (Кремль, собор, статуя)

Qwen, одно фото, без болванки, режим RGBA: «перерисуй в изометрии как спрайт, вырежи только здание». ~2 мин, прозрачный фон сразу на выходе. Такое здание в мире одно, поэтому генератор разворачивает под нарисованный ракурс участок, второй вид получается зеркалом. Подсказка «крутой вид сверху» словами работает слабо, поэтому для наклона 55° нужна болванка.

### R5. Новый тип дома по описанию → канонический вид

Qwen по тексту, RGBA, ~75–90 с. Стиль держится ровно между странами (машия, шале, риад, купеческий дом, изба). Ракурс модель выбирает сама. Получившийся вид дальше становится референсом для R2 или R3.

### Брак, нарезка, контроль

- **Починка ячеек** (`fix_cells.py`): в сломанную ячейку подставляется её болванка, и ячейка перерисовывается по маске с силой 0.6. Остальной лист служит контекстом и остаётся пиксель в пиксель.
- **Нарезка** (`tools/ai/cut_sheet.py`): лист превращается в RGBA-спрайты с общим масштабом и точкой привязки, плюс зеркальные ракурсы и `sprites.json`.
- **Автопроверка** (`qscore.py`): IoU силуэта против `_mask`. Порог 0.95, ниже — перегенерировать с другим сидом. Для листа передавайте `single=False`, иначе засчитается только одно здание.
- **Сколько брака:** ~1 из 4–8 сидов уходит мимо, особенно анфас (0°).

## Что НЕ работает (не повторять)

| Попытка | Что выходит |
|---|---|
| Z-Image без болванки | свой ракурс и свои пропорции |
| Z-Image, ControlNet по глубине или по серой болванке | форму не держит или просто раскрашивает болванку |
| Z-Image, `denoise ≥ 0.89` при 8 шагах | исходник **молча игнорируется**: рабочие значения — это «пропустить шаг», 0.85 и 0.75 |
| Z-Image без линий окон на многоэтажке | 1–3 этажа вместо пяти, особенно на крутом наклоне |
| Линии окон ≥0.45 или ячейки 384 px | плоские «панельные» фасады |
| Qwen: фото первой, болванка второй | копирует ракурс фото, IoU ~0.44 |
| Qwen: только ControlNet (без болванки-образца) с силой 1.0–1.4 | **рисует оранжевую коробку** |
| Qwen: болванка без ControlNet при крутом наклоне (55°) | съезжает к привычным ~30–35° |
| Qwen: картинка-«эталон стиля» третьим образцом | **копирует сам объект** с эталона |
| Холст больше 2 Мп на Mac | падает в VAE |

## Камера и видимость персонажей

- Здание высотой h закрывает за собой полосу улицы длиной **h·ctg(наклона)**.
- Доля улиц, скрытых целиком для человека ростом 1.7 м, по настоящим городам из генератора:

  | Город | 30° | 45° | 55° | 60° | Движок сейчас |
  |---|---|---|---|---|---|
  | Москва | 24% | 16% | 11% | 9% | 10% |
  | Париж | 42% | 32% | 25% | 22% | 22% |
  | Нью-Йорк | 50% | 45% | 39% | 36% | 37% |

  Пересчитать: `node tools/ai/lab/occlusion.js`, `occlusion_streets.py`; картинка с людьми — `occlusion_view.py`.
- **Текущая проекция движка** (земля не сжата, высоты ×0.6) по видимости равна камере с наклоном ~59°, но это не настоящая камера.
- **Модели хорошо рисуют любой наклон 30–60°** (Z-Image, анфас IoU 0.91–0.98).
- **«Вид 3/4» — это и есть такая камера:** она смотрит на город с юга под наклоном. Наклон рёбер 2:1 бывает только у домов, повёрнутых на 45°.
- **Рекомендация:** наклон ~55°, плюс силуэты людей сквозь здания и полупрозрачность домов вокруг выбранного персонажа. Даже при 55° в плотных кварталах скрыта четверть-треть улиц.

## ChatGPT как внешний источник листов

- ChatGPT рисует ортографическую камеру и держит углы ±4°, если в промпте прямо сказано следить за углами. Без этого 30° и 60° тянутся к 45°.
- Наклон камеры от листа к листу гуляет: 22–41°.
- **Каждый лист замерять:** `tools/ai/measure_sheet.py SHEET OUT [pitch] [angles]`. Допуски: угол ±5°, наклон ±3°. Промахнувшиеся ракурсы перерисовывать по одному.
- **Подсказочные листы** с линиями, пятном застройки и болванками: `tools/ai/angle_sheet.py`. Пропорции болванки должны совпадать с пропорциями здания, иначе углы поедут.

## Открытые вопросы и следующие шаги

1. **Решить камеру движка.** Рекомендация — ~55°. Затем проверить рецепт листа R1 при 55°: все прогоны листов шли при 30°, а этажность на крутом наклоне надо держать линиями окон.
2. **Собрать автоматический конвейер** из готовых звеньев: тип дома и размеры из генератора → болванки → лист → проверка IoU → починка брака → нарезка → `sprites.json`.
3. **Автоматизировать описание дома по фото** для второго прохода в R2.
4. **Обучить LoRA стиля** на 30–100 отобранных спрайтах.
5. **Выбрать одну модель или связку.** Вариант на одном Qwen проще, но в 2–3 раза медленнее.
