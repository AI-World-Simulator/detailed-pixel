# Анимация персонажей: правила проекта

> **Главное (уточнение пользователя, 17.10.2026):** живое движение важнее неподвижности. Волосы, моргания, мимика,
> поворот головы в движении — хорошо. Запрещено только **кривое и бессмысленное** изменение пропорций и форм (голова
> вдруг меньше или больше, черты плывут, объём тела скачет) и ноги, которые скользят или парят. Голову **не
> замораживать** и не вклеивать из базового кадра поверх хорошей анимации — на облачных кадрах это всё сломало.

Свод правил для любой работы с анимацией жителей: лоадер, агенты на улицах, портреты.
Основание — исследование [reports/Анимация пиксельных персонажей.md](../reports/Анимация%20пиксельных%20персонажей.md)
(тайминги Stardew Valley, Pokémon, Habbo, Celeste, туториалы Saint11 и Slynyrd, замеры наших кадров).
Код, который эти правила исполняет: `tools/ai/anim.py` (кадры), `src/loader.js` (хореография).

## 1. Что видит зритель — в этом порядке

1. **Лицо.** Глаза получают первую фиксацию взгляда, поэтому лицо — главный источник и жизни, и брака. Осмысленное движение (моргание, мимика, поворот головы, волосы, качающиеся при шаге) делает анимацию живой. Бессмысленный шум (пиксель пропал в одном глазу, черты «поплыли», голова вдруг стала меньше) читается как ошибка: один пиксель на голове в 15–20 px — 5–7 % её высоты, такое замечают почти всегда.
2. **Контакт с землёй.** Ступни на одной линии во всех кадрах с опорой; иначе персонаж «парит» или «топает».
3. **Ритм.** Ровные интервалы и синхронность — признак дешёвой анимации. Структура регулярна (цикл ходьбы), события нерегулярны (моргания, паузы, жесты, фазы разных персонажей).

## 2. Инварианты кадров (нарушение = брак)

| Инвариант | Правило | Как держим |
|---|---|---|
| Пропорции и формы | размер головы, расположение черт, объём тела не скачут между кадрами; движение волос, глаз, мимики и поворот головы — **желательны** | проверять масштаб головы и площадь силуэта; шум пиксельизатора лечить фазой сетки; голову **не замораживать** |
| Сетка | один размер пикселя, все кадры режутся в фазе базового кадра | решётка базы, сдвинутая на дрейф головы; никакого `scale`/`rotate` пиксель-арта |
| Палитра | одна палитра на персонажа, построена от базового кадра, без «близнецов» | слияние цветов ближе L1 ≈ 12, несколько слотов только для новых предметов |
| Опора | нижний ряд обуви = линия земли базы | постановка по контакту ног, горизонталь — по торсу; кадры в воздухе помечены явно |
| Объём | площадь силуэта ±8 % от idle (кроме помеченных сжатий) | QA |
| Контур | 1 px, без «двойных» блоков 2×2, доля контура на краю ≥ 88 % | QA, чистка изолированных пикселей |

Совмещать кадры по совпадению цвета **нельзя**: оно приклеивает голову и торс, и присевший персонаж повисает.

- *Только для локального конвейера (правки Qwen + пиксельизация):* голова может опускаться сколько угодно (присед, кивок), но подниматься над idle не больше чем на 1 px — модель рисует позу на пару пикселей выше, и персонаж «вытягивается».
- Правка выражения (смех, моргание) меняет только внутреннюю часть лица; уши, волосы и контур остаются из базы, иначе по краям головы появляются пятна.
- Кадр сжатия должен сохранять выражение: подскок со смехом использует `squash_laugh`, а не `squash` из idle, иначе лицо мигает «смех → открытые глаза → смех».
- Моргают все, включая занятых работой и идущих: у каждого позового кадра есть двойник `<кадр>_blink` (глаза из кадра моргания, сдвинутые вместе с головой позы — как накладка глаз у Stardew). Сцена подставляет двойника раз в 2–5,5 с.
- Закрытые глаза модель рисует линией тоньше клетки — при уменьшении она пропадает, и «моргание» не отличается от idle. Проверять число изменившихся клеток; если их почти нет, собирать моргание из базовых глаз (нижний ряд глаза остаётся, выше — кожа).

## 3. Бюджет кадров и тайминги (чиби ~43 арт-px, вид 3/4)

Игры обходятся 2–3 рисунками на действие; качество делают таблицы таймингов и задержки.

| Действие | Рисунков | Тайминг |
|---|---|---|
| Ходьба | 3 в петле из 4: шаг A, стойка, шаг B, стойка | 150–200 мс на кадр; тело на 1 px выше в стойке («проход») |
| Idle / дыхание | 1–2 + моргание поверх | смена раз в 1,6–3 с, ±1 px |
| Моргание | 1 закрытый кадр | 100–160 мс; интервалы 2–6 с случайно; ~15 % двойных; тройных никогда |
| Разговор | 2 состояния рта, только голова | 110–190 мс на взмах, неровно; пауза-«слово» 250–400 мс каждые 3–6 взмахов; реплика кончается закрытым ртом |
| Взмах рукой | 2, только рука | 300–400 мс |
| Присесть и положить | однократно | стоит 300 → присел 600 → встал 500 мс; результат (плитка) появляется, когда встаёт |
| Копание | неровно | по образцу Stardew 150/40/40/170/75 мс: долгий замах, удар, задержка |
| Кисть, мелкая работа | 2 в петле | 350–400 мс с небольшим разбросом |
| Подскок радости | присед → отрыв → апекс → падение → приземление | 110 / 70 / 60 / 150 / 60 / 60 / 100 мс, высоты 0/2/4/5/4/2/0 px; отдых каждый раз разный |

- Сжатие (squash) — **отдельный кадр**, не `transform: scale` (смешает размеры пикселей). Дёшево: убрать из idle один ряд на уровне колен.
- Подскок неподвижного кадра вверх-вниз без приседа и приземления = «воздушный шар».
- Предвосхищение (присед) запрещено только у персонажа под управлением игрока (задержка ввода); жителям — можно и нужно.

## 4. Конвейер ИИ → пиксели

**Генерация**
- Каждая правка от базового кадра («звезда»), не от предыдущей («цепочка» накапливает дрейф лица и цвета). Цепочку используем только для слоёв мира (остров), с подгонкой тона.
- Холст правки кратен 16 и равен референсу (768×768): штатный узел Qwen иначе перемасштабирует референс и сдвигает картинку.
- Оговорка в промпте «всё остальное не меняй» не даёт измеримого эффекта; позовые правки Qwen рисуют голову на 8–12 % меньше — это **бессмысленное** изменение пропорций, его стоит ловить проверкой масштаба головы и перегенерировать (или править только ниже шеи).
- OpenPose плохо работает на чиби (1–4 головы в росте). Позу надёжнее задавать глубиной/контурами от «перегнутой» базы через Fun ControlNet Union (сила 0,65–0,80).
- Видеомодели (Wan, LTX) и интерполяция RIFE/FILM для пиксель-арта не годятся: морфинг, размытие, выход за палитру.
- Светлые объекты без контура (газета, снег) цветовое удаление фона съедает → маска BiRefNet ∪ цветовой способ.

**Постобработка (`anim.py char`)**, порядок шагов:
1. Сетка базового кадра; каждый кадр режется этой решёткой, сдвинутой на дрейф головы (фазовая корреляция по кропу головы).
2. Палитра от базы, близнецы слиты; кадры маппятся к ближайшему цвету без дизеринга.
3. Постановка на землю по ряду обуви, горизонталь по торсу.
4. *Костыль локального конвейера:* голова из базы в позовых кадрах Qwen (там лицо ломает пиксельизация). К хорошим кадрам (облачные сервисы) не применять — убивает живое движение.
5. Чистка изолированных пикселей.
6. QA (`anim.py qa`): контакт с землёй, масштаб головы и площадь силуэта, новые цвета, шум, контур + полоса onion skin. «Лицо отличается от idle» — **не** брак: моргание, мимика и волосы так и должны выглядеть.

## 5. Хореография и рантайм

- **Скорость из шага, не наоборот:** скорость = длина шага × шагов/с. Шаг измеряется по кадрам контакта (у наших жителей 9–10,5 px). Скользящие ноги («лунная походка», «марш на месте») — самый заметный дефект движения.
- **Темп пикселей кратен кадру экрана:** 30 px/с (33,3 мс = 2 vsync), 20 px/с (50 мс = 3 vsync), 15 px/с (дальний план). 25 px/с даёт микродрожание.
- **Рассинхрон:** у каждого персонажа свои длины петель (лучше взаимно простые: 7,3 / 8,9 / 10,7 с) и свой генератор с зерном; никакие двое не моргают в один тик.
- **Моргание по поводу:** после конца реплики собеседника (0,25–0,5 с), при повороте; случайные заполняют промежутки. Работающие тоже моргают.
- **Разговор:** пауза между репликами в сцене 300–600 мс; пиктограмма в пузыре висит ≥ 0,8 с; смех вразнобой.
- **Одно главное действие за раз:** говорит один, прыгает один; остальным — тихая жизнь (моргания, кивки, дыхание).
- **Шествие/толпа:** неровные интервалы между идущими (ровные = конвейер); у каждого своя длительность кадра из своего шага. Без кадров ходьбы персонаж не скользит, а стоит.

**CSS**
- Только `transform` и `opacity` (compositor) — сцена живёт, пока главный поток занят (проверено: 109 разных кадров за 3 с блокировки).
- Неровный тайминг — отдельный ключевой кадр на каждую задержку + `step-end` (`track()` в `loader.js`); `steps(n)` даёт только равные кадры.
- Каждая независимая дорожка transform — на своей обёртке. Дорожки одного персонажа — одинаковой длины и назначаются в одной задаче.
- Масштаб только целый, все сдвиги кратны арт-пикселю, `image-rendering: pixelated`.
- `prefers-reduced-motion`: движения нет, моргание можно оставить.

## 6. Инструменты: локальные и внешние

«Только локально» — не догма; внешний сервис уместен, если он лучше и дешевле по времени.

| Инструмент | Что даёт | Цена / условия |
|---|---|---|
| ComfyUI: Z-Image-Turbo, Qwen-Image 2.1 Edit, Fun ControlNet Union, BiRefNet | наш основной конвейер | локально (`~/ComfyUI`, `tools/ai/cgen.py`) |
| **PixelLab** (animate with skeleton v3) | «Fixed head», заморозка и инпейнт кадров, скелет, целевая палитра, 3–15 кадров | облако/API/MCP, ~$0,04–0,06 за вызов; нельзя обучать модели на его выходах |
| **Retro Diffusion** (advanced animation) | ходьба/idle/прыжок/присед от стартового кадра, `input_palette` | облако, $0,14–0,25 за вызов; размеры фиксированы |
| **Aseprite** | onion skin, связанные cels, слайсы с pivot, CLI-экспорт листа с длительностями | коммерческая программа; полезна для просмотра и QA и без рисования |
| unfake, PixelOE, K-Centroid, Pixel Snapper | даунскейл, сохраняющий тонкие тёмные линии (`dominant`, `contrast`), фиксированная палитра | открытые |
| Узлы ComfyUI: Image Edit Difference Mask (WepeNerd), LockPixel Pad, Pixel Drift Fix | диф-маска с вето («Fixed head» локально), замер и возврат дрейфа | открытые |
| TexturePacker / Spine / Rive | pivot на кадр / скелет / state machine | для нашего лоадера не нужны: холст единый, Spine и Rive ломают пиксели или тяжелы |

Проверено на наших жителях ([tools/loader/cloud/RESULTS.md](../tools/loader/cloud/RESULTS.md)): оба сервиса дают
живое движение (6–9 кадров: волосы, моргания, мимика, поворот головы) и **по оценке пользователя лучше нашего локального
конвейера во всех действиях**. Кадры брать как есть — вклейка головы и перекраска их ломают. Retro Diffusion —
только с `remove_bg: true` (иначе `custom_action` заливает фон). PixelLab рисует эффекты (искры, «zz», плюсики,
следы руки при взмахе, пылинки) **даже с запретом в промпте**; лоадер теперь на его клипах, и эффекты снимает
`tools/loader/cloud/pack_cloud.py`. Правило: у персонажей PixelLab есть тёмный контур, у эффектов его нет, поэтому
светлое пятно, которое большей частью касается пустоты, считается эффектом. Плюс к этому убираются его остатки,
светлые и мелкие парящие кусочки. Тёмные отлетающие куски (земля с лопаты, камень) остаются. Если эффект с контуром
прилип к руке, кадр выкидывается (`EXCLUDE`), а не дорисовывается.

## 7. Чек-лист перед показом

- [ ] `anim.py qa` без провалов (или провальные кадры выкинуты/перегенерированы).
- [ ] Пропорции и формы не скачут (голова, черты, объём тела); лицо меняется только осмысленно — моргание, мимика, поворот, волосы.
- [ ] Ступни на линии земли во всех кадрах с опорой (смотреть запись в ×3).
- [ ] Ноги не скользят при ходьбе (смотреть на запись, а не на скриншот).
- [ ] Никто не моргает синхронно; у каждого свои петли.
- [ ] Подскоки с приседом и приземлением; работа с неровным таймингом.
- [ ] Паузы между репликами 300–600 мс, реплики кончаются закрытым ртом.
- [ ] Проверены ширина 360 px и `prefers-reduced-motion`.
